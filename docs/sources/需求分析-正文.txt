《多系统RBAC权限管理平台 - 需求规格说明书》
1. 引言
1.1 编写目的
本需求规格说明书（Req-spec）旨在明确“多系统RBAC权限管理平台”的业务需求、功能边界及设计约束。作为项目后续的界面原型设计、API设计、数据库设计及编码测试的依据。
1.2 设计思想约束根据课程要求，本系统在开发过程中必须严格贯彻以下三种软件工程思想：
1. 结构化设计：后端严格遵循 Controller - Service - DAO 三层架构；前端按业务模块化划分目录。2. 面向对象设计 (OOP)：实体类必须抽取公共父类（如 BaseEntity），通过继承和多态管理复杂权限关系。3. 函数式设计 (FP)：在处理权限集合过滤、数据流转换时，强制使用 Lambda / Stream API 等高阶函数，避免副作用。
2. 总体描述
2.1 系统目标
构建一个支持多系统隔离、基于 RBAC0 模型的基础统一权限管理中心。管理员可以在一个平台内，方便地管理各个子系统的权限变更。
2.2 用户角色
· 超级管理员：拥有所有系统的最高权限，可进行多系统配置、权限变更审计。· 系统管理员：仅拥有特定系统（如系统A）的管理权限，不可越权操作其他系统。· 普通用户：仅能访问被分配的系统及对应的功能菜单。
3. 功能需求
3.1 多系统管理模块
· 支持创建、修改、停用子系统。· 系统必须记录 sys_id，用户在登录时需选择或携带 sys_id，后端需根据该 ID 进行数据隔离。
3.2 RBAC0 核心权限模块
· 用户管理：用户的增删改查。· 角色管理：角色的增删改查。· 权限/菜单管理：菜单树与按钮权限的配置。· 权限分配：支持为用户赋予角色、为角色赋予权限（关联表操作）。
3.3 权限变更与审计模块
· 任何针对“用户-角色”或“角色-权限”的变更操作，系统必须在后台静默生成一条审计日志（记录操作人、操作时间、目标系统、变更前后的值）。· 前端提供审计日志查询界面，方便追溯权限变更。
4. 非功能需求
4.1 安全性需求
· 后端必须实现统一的权限拦截器。用户发起的任何请求，必须校验其当前 sys_id 下是否具备对应的权限标识，否则返回 403 Forbidden。· 严禁越权访问，普通用户不能通过篡改 URL 或参数访问管理员接口。
4.2 性能与交互需求
· 前端登录后，需根据后端返回的权限树，动态生成左侧菜单（动态路由）。· 界面需友好，无权限的按钮需隐藏或置灰。
