= 第一次检查：后端联调与现场演示

== 当前完成度

本轮在 V1.2 设计基线上新增可运行 Java 后端，形成第一次检查的核心闭环：

* 前端界面：已有独立 HTML 与 Vue 离线原型；后端另提供 `http://localhost:8080/` 联调控制台。
* 数据库设计：保留 11 表 MySQL DDL、字典、ER 图；后端默认使用同结构的 H2 演示库，另提供 MySQL 运行配置与演示口令脚本。
* 面向功能 RBAC0：登录、会话、系统切换、角色/权限/成员读取、成员角色替换、角色权限替换、有效权限、动态菜单、审计读取。
* 统一鉴权：Bearer 会话、账号/系统/成员安全门、路径 `sysId` 一致性、`@RequirePermission` 静态权限码。
* 测试与覆盖率：5 个自动化测试全部通过，JaCoCo 报告已生成。
* 详细设计 E：E 模块 2 份 adoc + 3 份 PlantUML 已补入 `docs/detail-design` 与 `uml/detail-design`。

尚未完成的边界：38 个端点没有全部实现；当前缓存为单实例内存缓存；公网服务器部署和 Gitee/课程网站提交仍需小组执行；MySQL 实库需在具备管理员权限的 MySQL 服务上运行脚本并保存输出。

== 启动方式

[source,powershell]
----
cd backend
.\mvnw.cmd spring-boot:run
----

浏览器打开 `http://localhost:8080/`。默认 H2 内存库启动时自动建表并写入演示数据，重启即恢复初始状态。

演示账号密码均为 `DemoOnly12345`：

* `platform_admin`：平台管理员，可进入任一系统。
* `system_admin`：系统 A 系统管理员，系统 B 成员查看员。
* `auditor`：系统 A 审计查看员，系统 B 系统管理员。
* `chenyu`：两个系统均为成员查看员。
* `lichen`：账号停用，用于演示 401。

== 五分钟演示脚本

. 用 `platform_admin` 登录系统 A，指出策略版本、18 个权限码和 4 个根菜单。
. 选中陈雨，把“成员查看员”换成“审计查看员”，保存。说明请求带 `If-Match`，事务同时写关联、版本和审计。
. 退出并用 `chenyu` 登录系统 A。权限只剩 `menu:audit`、`sys:audit:read`，菜单只剩审计日志。
. 点击系统 B。同一陈雨恢复成员查看员权限，证明权限事实按 `sys_id` 隔离。
. 打开 `backend/target/site/jacoco/index.html`，展示自动化测试与覆盖率。

== 建议现场说明

“系统把用户、成员、角色、权限分成全局账号和多系统成员。当前请求先通过会话安全门读取账号、系统和成员状态，再按当前系统的角色与权限计算并集。菜单不是权限来源，只是权限码的展示投影；接口拦截只使用 ACTION 码。写授权时在事务中递增系统策略版本，缓存键随之变化，所以撤权后不会继续命中旧权限缓存。”

“路径里的 sysId 必须和会话上下文一致，SQL 查询也都显式带 sys_id。拦截器解决‘有没有权限’，对象 SQL 解决‘能不能看见这条数据’，两层不能互相替代。”

== 常见答辩问题

. 为什么 MENU 和 ACTION 都进入权限集合？
   MENU 决定页面入口，ACTION 决定接口调用；二者独立，不能相减或推导。
. 为什么菜单要补父容器？
   只授权子菜单时前端树仍需要父节点；父节点只作容器，`navigable=false`，不代表额外授权。
. 为什么缓存键带 policyVersion？
   撤权后版本递增，旧缓存键不会再被新请求命中，避免旧权限延长生效。
. 平台管理员是否能跨系统读取？
   不能。平台管理员进入某系统后只使用该系统的上下文和已注册权限。
. ETag 解决什么问题？
   防止两个管理员基于旧集合互相覆盖，版本不一致返回 412。
